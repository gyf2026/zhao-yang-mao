# 定时巡检提示词模板

用户要定时巡检时，用 `automation_update` 创建，把下面的提示词作为任务内容。排班（如每 2 小时）写进 rrule，不要写进提示词。先问用户是否真要开启，不要擅自创建。

## 提示词

```
使用 deal-hunter 技能执行一轮巡检（定时模式）。

范围：
A) 什么值得买好价：首页 + 好价频道翻 1-2 页，并按 ~/.workbuddy/deal-hunter/watchlist.md 的关注清单逐品类搜索。
B) X（x.com）羊毛福利与 AI 免费额度：浏览已登录账号的首页与关注流。

全程只读，严禁下单、领券、加购、发帖、点赞、关注、提交表单、输入凭据，不切换账号。
按技能中的推送门槛、时效核验、去重与落盘规则执行。
最终回复就是推送正文本身：两节都有按"【好价】…／【羊毛】…"合并；只有一节只发该节；都没有则回复空字符串。
浏览器登录态失效、被占用超过 15 分钟或整轮超过 45 分钟，则记录 skipped.log 并静默结束，不推送半成品。
```

## 建议

- 频率：每 2 小时一轮足够；好价帖通常几小时内就被抢完，过密只会增加风控风险。
- 加时间窗：只在 08:00–23:00 运行，夜间无意义。
- 浏览器是共享资源：电脑上同时有其他任务用浏览器时，本轮会因占用被跳过。
- 关注清单要常更新：删掉不再关心的品类，轮次耗时才可控。
