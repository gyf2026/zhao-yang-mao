# 定时巡检：排班、前置条件与提示词

> 定时巡检不是"配好就忘"。它依赖**电脑开着、网络通着、浏览器登录态有效**这三件事。
> 任何一条断了，任务都会静默失败——而静默失败最坑，因为用户以为它在盯，其实早就停了。

---

## 一、先跟用户确认，别擅自开

用户说"帮我盯着"不等于"现在就把定时任务建起来"。**先问清四件事**，用 `AskUserQuestion` 给选项：

1. **频率**：每 1 小时 / 每 2 小时（推荐）/ 每 4 小时 / 每天两次
2. **时间窗**：全天 / 08:00–23:00（推荐）/ 只在白天工作时段
3. **范围**：只推好价 / 只推羊毛与 AI 额度 / 两者都要
4. **推给谁**：当前会话 / 指定渠道

拿到答案再用 `automation_update` 创建，排班写进 `rrule`，**不要写进提示词**。

---

## 二、⚠️ 必须提醒用户：电脑不能关、不能睡

这是定时巡检最常见的失效原因。**建任务前一定把这段讲给用户**，别等三天后用户问"怎么没动静"。

**核心一句**：**电脑一旦休眠/睡眠，这一轮扫描就不会执行。** 睡眠时进程被冻结、网络断开，浏览器和脚本都跑不起来；而且任务**不会在醒来后补跑**，只是白白错过这一轮，等下一轮触发才恢复。所以不是"慢一点"，是"这一轮直接没了"——好价帖通常几小时内就抢完，错过就是错过。

### macOS

| 要设置的 | 在哪设 | 说明 |
|---|---|---|
| 防止自动睡眠 | 系统设置 → 锁定屏幕 → 「未活动时关闭显示器」调长；电池 → 「电源适配器连接时防止自动睡眠」 | 插电时基本不会睡 |
| **合盖不睡眠** | 需外接显示器 + 电源，或用第三方工具 | 笔记本**合盖默认必睡**，睡了任务就不跑 |
| 临时保持唤醒 | `caffeinate -dimsu` | 期间不休眠；`Ctrl+C` 结束。可挂在巡检窗口上 |

一句话建议：**插着电源、开着盖、别手动点睡眠**。

### Windows

| 要设置的 | 在哪设 | 说明 |
|---|---|---|
| 接通电源时永不睡眠 | 设置 → 系统 → 电源和电池 → 屏幕和睡眠 → 「接通电源时，使设备进入睡眠状态」设为**从不** | 关键一条 |
| **合盖动作** | 控制面板 → 电源选项 → 选择关闭盖子的功能 → 接通电源时选「**不采取任何操作**」 | 笔记本合盖默认睡眠，必须改 |
| 关闭「快速启动」副作用 | 电源选项 → 选择电源按钮的功能 | 部分机器快速启动会让定时任务错过触发 |
| 网络唤醒断开 | 设备管理器 → 网卡 → 电源管理 → 取消「允许计算机关闭此设备以节约电源」 | 否则待机久了断网 |

一句话建议：**插电、合盖设为不操作、电源计划里睡眠设为「从不」**。

### 网络

- Wi-Fi 在睡眠/省电时可能断开，恢复后任务已错过 → 尽量插网线，或关闭无线网卡的省电模式。
- 代理软件（Clash / v2rayN 等）**必须保持运行**，否则境外站（X、Slickdeals）全部拉不到。设成开机自启。
- 定时任务触发的瞬间如果网络还没连上，本轮会失败——通常下一轮会自愈，不必紧张。

## 三、登录态：只用 cookie 免登，不碰账号密码

- **登录动作由用户自己完成**：Agent 把登录页切到前台，用户扫码或输验证码/密码。Agent **不索要、不输入、不保存任何账号密码**，也不切换账号。
- Agent 只做一件事：登录成功后导出 cookie 存到本机 `~/.workbuddy/deal-hunter/cookies/`，下次启动浏览器时带上，免去重复登录。cookie 等同于本机浏览器里本来就有的登录态，只存在用户自己电脑上。
- cookie 过期后，X 会跳登录页，本轮抓到的正文只有一百来字。**建议每 1–2 周检查一次登录态**。
- 技能侧的处理：识别到登录墙（URL 含 `/login` 或 `onboarding`，正文极短）→ 记录 `skipped.log`，**本轮静默结束，不推送**，并在下一次成功运行时提示用户"登录态可能已过期，请重新登录一次"。
- **绝不尝试自动登录、自动过验证码、绝不用密码去换 cookie。**

---

## 四、频率与时间窗

- **每 2 小时一轮足够**。好价帖通常几小时内就被抢完，再密只是徒增风控风险和机器负担。
- **加时间窗，只在 08:00–23:00 运行**。夜间没有新爆料，纯浪费；也避免半夜推送吵人。
- 大促日（618 / 双 11）可以临时调到 1 小时，活动结束记得调回来。
- 关注清单越长，单轮耗时越长；超过 45 分钟就该砍品类了。

## 五、提示词模板

```
使用 deal-hunter 技能执行一轮巡检（定时模式）。

范围：
A) 什么值得买好价：首页 + 好价频道翻 1-2 页，并按 ~/.workbuddy/deal-hunter/watchlist.md 的关注清单逐品类搜索。
B) X（x.com）羊毛福利与 AI 免费额度：浏览已登录账号的首页与关注流。

全程只读，严禁下单、领券、加购、发帖、点赞、关注、提交表单、输入凭据，不切换账号。
按技能中的推送门槛、时效核验、同款去重与落盘规则执行：
- 同款商品只推一次，除非本次价格比历史推送最低价再低 1%（判定用 ledger.py check，不看链接看商品）。
- 扫到的每个候选都要记 scan.jsonl（推的记 add，没推的记 scan 并写剔除原因），不记账视为本轮未完成。

最终回复就是推送正文本身：两节都有按"【好价】…／【羊毛】…"合并；只有一节只发该节；都没有则回复空字符串。

异常处理：
- 浏览器登录态失效、被占用超过 15 分钟、整轮超过 45 分钟 → 记录 skipped.log 并静默结束，不推送半成品。
- 电脑睡眠/断网导致失败 → 本轮作废（不会补跑），下一轮自愈，不要补推。
```

## 六、建好之后的检查清单

- [ ] 已提醒用户：电脑不能关机、不能睡眠（**休眠这一轮就不执行，且不会补跑**）、代理软件要保持运行
- [ ] 已说明登录方式：**用户自己登，Agent 不存账号密码，只存 cookie 免登**
- [ ] 已确认频率与时间窗（默认每 2 小时、08:00–23:00）
- [ ] 登录态已存在 profile 里，并且 dumpcookie 备份过
- [ ] 手动跑一轮验证过：能抓到、能落盘、能记账（pushed + scan）、能正确推送
- [ ] 知道怎么看 `skipped.log`（连续多轮跳过 = 出问题了）

---

## 七、连续失败要主动说

静默跳过是**单轮**的规则，不是永远闭嘴。如果 `skipped.log` 里连续 3 轮以上都有记录，说明是系统性问题（登录过期 / 代理挂了 / 浏览器被占用），**下一次成功运行时主动提醒用户**：

> 顺带说一句：最近几轮巡检都被跳过了，原因是登录态可能已过期，需要你重新登录一次。

别让用户以为还在盯着，其实早就停了——这比漏推几条好价严重得多。

---

## 八、想停就停

- 用户说"别盯了" → 停掉定时任务，并告知：数据目录 `~/.workbuddy/deal-hunter/` 里的关注清单和推送台账会保留，随时可以再开。
- 临时暂停（如出差）→ 把任务设为 `PAUSED`，不要删，回来再恢复。
