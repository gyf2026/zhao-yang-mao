# 首次使用：自检 → 装浏览器 → 问方向 → 定计划

**这份文档是给 Agent 的执行剧本，不是给用户读的说明书。** 第一次在这个环境里跑本技能，必须按顺序走完，不许跳步直接开扫。

顺序不能颠倒：**先确认能不能跑，再问用户想要什么，最后才排班。** 反过来做，会出现"计划建好了、每天准点空跑"这种最糟的结果。

---

## 第 0 步：Agent 先自检「我有没有浏览器控制能力」

这一步脚本查不了，只能 Agent 自己回答。**不许糊弄过去，不许默认"应该能用"。**

按下面四个问题逐个回答，答不出来就是没有：

| 问题 | 怎么算「有」 | 怎么算「没有」 |
|---|---|---|
| 1. 我有没有能开浏览器的工具？ | 有 browser / browser-use / playwright / CDP 之一 | 只有 http 抓取工具 → **没有** |
| 2. 开出来的是真浏览器窗口吗？ | 屏幕上真有一个窗口，用户能看见、能自己操作 | 只拿到 HTML 字符串 → **没有** |
| 3. 这个窗口能持久保存登录态吗？ | 有固定的 profile 目录，关掉再开还是登录状态 | 每次都是干净的临时 profile → **等于没有** |
| 4. 我能读到 cookie 并导出吗？ | 能拿到 cookie 并落盘复用 | 拿不到 → **等于没有** |

### 各宿主环境的已知情况（别人踩过的坑，别重踩）

| 宿主 | 浏览器能力现状 | 结论 |
|---|---|---|
| **WorkBuddy** | 内置浏览器控制在连接失败时**静默回退到自带 Chromium**：屏幕上那个 Chrome 收不到指令，却回「✓ Done」，读到的是另一个浏览器的页面。而且它起的浏览器**活不过一次命令调用**。 | **必须用外置浏览器 + CDP**（`browser-cdp-control` 技能）。不要用内置那套 |
| **QQ 浏览器（配合 WorkBuddy）** | 本机实测可用，Chromium 内核，支持 `--remote-debugging-port`。国内环境打开国内站更顺手 | 可作为 Chrome 的替代，出怪问题时优先换回 Chrome 对照 |
| **Hermes / OpenClaw / ChatGPT（含 Computer Use 类）** | 通常**有内置浏览器**，能点能读 | **仍然建议改用外置浏览器**。原因：内置浏览器的 profile 多为临时目录，关掉即丢，登录态存不住；而登录是 X、LINUX DO 这类源的命门。只能用它的时候，要明确告诉用户「登录态无法保存，每轮都要你手动登一次」 |
| **纯 CLI Agent（无浏览器工具）** | 没有 | 只能跑 A 段直连（smzdm / V2EX）；B 段要用户自己看，**必须如实说明能力边界**，不许假装扫了 |

**判断口径再强调一次**：能拿到 HTML ≠ 有浏览器。这个技能要浏览器，要的是**能过 Cloudflare、能保存登录 cookie、用户能在窗口里自己扫码**。拿不到登录态的"浏览器"，对 X 和 LINUX DO 等于零。

---

## 第 1 步：跑环境自检

```bash
cd <技能目录>
python3 scripts/doctor.py
```

七项检查：系统与 Python、外置浏览器、CDP 通道、代理、网络、数据目录、登录态。

- 退出码 `0` = 可以跑（可能有 `!` 警告）
- 退出码 `1` = 有条件阻塞（缺浏览器或缺 CDP 通道）→ 只能跑直连部分
- 退出码 `2` = 致命（Python 版本不够）

机器可读：`python3 scripts/doctor.py --json`；不想发任何请求：`--no-net`。

---

## 第 2 步：按自检结果补齐（缺什么补什么）

### 2.1 没有 CDP 启动器 → 装 `browser-cdp-control` 技能

本技能所有浏览器操作都走它，不自带。装完再跑一次 `doctor.py` 确认「浏览器控制通道」变 `✓`。

### 2.2 没有 Chromium 内核浏览器 → 按这张表装

**只有 Chromium 内核能用 CDP 调试协议。** 这不是偏好问题，是兼容性问题。

| 浏览器 | macOS | Windows | Linux | 评价 |
|---|---|---|---|---|
| **Google Chrome** | ✓ | ✓ | ✓ | **首选**。CDP 支持最完整，出问题最好查 |
| **Microsoft Edge** | ✓ | ✓ 系统自带 | ✓ | Windows 上**不用另装**，直接用，效果等同 Chrome |
| **QQ 浏览器** | ✓ | ✓ | — | 国产 Chromium，国内站点体验好，WorkBuddy 环境配合较顺 |
| **Brave / Chromium** | ✓ | ✓ | ✓ | 备选 |
| Safari | ✓ | — | — | **不能用**。走 WebDriver，不支持 CDP |
| Firefox | ✓ | ✓ | ✓ | **不推荐**。CDP 协议不兼容，脚本会报找不到 target |

装完告诉用户：**登录要在装好的这个浏览器里做**，因为 cookie 存在它的 profile 里，换浏览器等于重新登一次。

### 2.3 代理连不上 → 让用户先把代理软件开起来

- 境外源（X / Slickdeals / DealMoon / OpenRouter）必须有代理，建议设开机自启。
- **国内站必须绕开代理**，否则流量从海外机房出去，会被当成异常 IP。直连脚本已内置 `--noproxy`。
- 代理端口会变，**每次以 `env | grep -i proxy` 的实时值为准**，不要用记下来的旧端口（写错会得到 `ERR_PROXY_CONNECTION_FAILED`）。

### 2.4 台账是空的 → 说明还没真跑过

`doctor.py` 会提示「空台账」。**这时候不要急着建定时任务**，先手动跑通一轮（见 `SKILL.md` 标准流程），确认从抓取到记账整条链路是通的。

## 第 3 步：问用户三件事（装好之后才问）

自检过了、浏览器装好了，再用 `AskUserQuestion` 问。**用选项问，不要开放式提问**——开放式问「你想找什么」，用户大概率回一句「随便看看」，等于没问。

### 必问 1：方向

| 选项 | 说明 |
|---|---|
| 特定商品/型号比价 | 有明确目标（如某型号显卡、某款相机），求最低价 |
| 某品类好价 | 如血糖仪、家电、数码配件，按品类扫 |
| 日用快消 | 纸巾、粮油、日化，单价低、看省额比例 |
| 纯羊毛（券/试用/红包） | 话费、银行立减金、会员、免费试用 |
| AI 免费额度 | 各家 API credits、免费模型、试用名额 |

### 必问 2：推送频率与时间窗

给三档，别让用户自己填 cron：

| 档位 | 适合 | 代价 |
|---|---|---|
| 每 2 小时，08:00–23:00 | **默认推荐**。好价几小时被抢完 | 一天 8 轮，电脑得一直开着 |
| 每 4 小时，09:00–22:00 | 不想被打扰太频繁 | 慢半拍，秒杀类基本抢不到 |
| 每天 2 次（早 9 点 / 晚 8 点） | 只看羊毛和 AI 额度，不追秒杀 | 错过了当天最好的价 |

**顺带说清代价**：定时任务依赖电脑开着、不休眠、网络通、登录态有效。休眠期间不会执行、也不会醒来补跑。

### 必问 3：范围

国内 / 含海淘 / 含 X 与 AI 额度。海淘和 X 要走代理，且 X 需要登录。

---

## 第 4 步：落配置、建计划

1. 把方向写进 `watchlist.md`（格式参考 `assets/watchlist.example.md`），下一轮不再问。
2. 用 `automation_update` 建定时任务，提示词模板见 `references/automation-prompt.md`。
3. **建之前把三条硬前提讲给用户**：电脑不休眠、代理常开、登录态可能过期（Agent 不碰密码，只存 cookie）。
4. 建完立刻手动跑一轮，确认真的能出结果——**没跑通过的定时任务不算建好**。

---

## 一句话版本

**先 doctor，再看浏览器，再问方向，最后排班。** 任何一步没过，就如实告诉用户卡在哪，别用「计划已建好」掩盖「其实跑不起来」。
